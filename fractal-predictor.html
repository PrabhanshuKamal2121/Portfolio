(CASE STUDY · 02)

FRACTAL PREDICTOR

ML Engineering Python FastAPI PostgreSQL

When you train a machine learning model on messy, real-world export data, accuracy isn’t gifted, it’s earned. We took a commercial ML model for Fractal Overseas from an 11.4% guess to a 78.6% precision engine, deployed on a robust FastAPI backend.

Role ML Engineer
Timeline Apr 2025 – Pres.
Year 2025
Team w/ Shivansh
(MY ROLE)

Conducted extensive Exploratory Data Analysis (EDA) and feature engineering to isolate shipping variables.

Trained and cross-validated ML models using Scikit-Learn to achieve 78.6% prediction accuracy.

Architected the FastAPI backend and integrated PostgreSQL for scalable data persistence.

Designed a custom HTML/JS frontend utilizing the Fetch API and Pydantic validation.

Approach

01

Data Wrangling

The first iteration hit exactly 11.4% accuracy. We put the algorithms on pause to strip out noise and engineer features that actually moved the needle on international shipping prices.

02

Model Tuning

Iterated through different models, tuned hyperparameters, and ran endless cross-validation loops until the model locked in at 78.6% precision.

03

API Architecture

A model stuck in a Jupyter Notebook is useless. We built a lightweight, asynchronous FastAPI backend to serve the model and handle real-world inputs instantly.

04

Live Deployment

Set up a CI/CD pipeline pushing straight from GitHub to Render, bridging the gap between raw data manipulation and a responsive, user-facing UI.

(PART 01)

From Notebook to Production

Taking this project from an 11% guess to a fully deployed 78% prediction engine meant mastering the entire pipeline—from data to dynamic UI.
